# Isolate failed events without bypassing workflow dependencies

Status: Accepted. Date: 2026-10-11. Decision: D-027.

Use durable quarantine and dependency blocking instead of endless partition-wide retries or blind failure skipping. Allow at most five total automatic attempts for isolated transient processing failures, with persisted counters and jittered delays up to 1/2/4/8 seconds; malformed/unsupported events quarantine immediately, while missing prerequisites remain pending for reconciliation. Commit original bytes/metadata, failure state, trustworthy workflow blocking, and DLQ mirror Outbox work atomically before advancing contiguous safe offsets. Quarantine is received, not applied. Independent orders may continue, but dependent work remains parked; unclear identity/dependencies, failed quarantine commits, or exhausted safe headroom pause the affected partition. Dependency-wide outages use backoff/circuit breaking. Preserve independently safe expiry/reconciliation, original deadlines, and D-006/D-023 provider dispatch guards. Alert and track blocked age; authorized audited recovery reprocesses unchanged events after a handler fix, and incorrect producer facts require new owner-issued correction events. Durable quarantine remains authoritative and unresolved work does not expire. Backlog limits, escalation SLOs, dependency mappings, replay roles/commands, and schemas remain unresolved.
