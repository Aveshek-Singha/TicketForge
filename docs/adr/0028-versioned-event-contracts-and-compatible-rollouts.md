# Version Kafka contracts and gate compatible rollouts

Status: Accepted. Date: 2026-10-11. Decision: D-028.

Use binary Protobuf for Kafka events with owner-controlled Git-versioned schemas, generated types, and pinned local tooling. A validated envelope carries stable event identity/type, contract version, owner aggregate/revision, correlation/causation, and occurrence time; replay retains exact original bytes. Within a major contract, preserve wire shape and business meaning, including tags, types, money units, enum meanings, and required-field rules; reserve removed tags/names. Unknown or unspecified financial states never mean success, and unsupported critical contracts follow D-027. CI uses local open-source Buf checks plus semantic, mixed-version, and archived replay fixtures. Deploy compatible consumers first, then enable producer output; breaking changes use a new major contract and controlled cutover with stable business-effect identities. Retain readers/descriptors for archived contracts and all unresolved older work, and define a tested compatibility release as the rollback floor. This adds generation and reader maintenance but prevents silent meaning changes and unsafe rollback; no paid registry is required. Exact envelopes, compatibility baselines, cutover gates, database migrations, and rollback procedures remain unresolved; choosing Kafka serialization does not choose RPC transport.
